# 局域网文件传输工具 — 设计文档(第一版)

- 日期:2026-06-09
- 技术选型:Go + Wails(编译成单个 exe,双击出窗口,免安装)
- 范围:第一版只做**局域网**;远程传输架构上留口子,后续迭代再加。

---

## 1. 目标与使用场景

做一个文件传输工具,满足:

- **设备范围**:同一局域网(同一 WiFi / 路由器)下的 电脑↔电脑、电脑↔手机 互传。
- **电脑端形态**:有窗口的桌面软件(能拖文件、看设备列表、看进度);内部同时跑一个网页服务给手机用。
- **手机端**:不装 App,扫码进网页即可传。
- **速度控制(用户重点)**:预设档位 + 实时显示速度 + 设上限限速 + 每个任务单独调。
- **分发要求**:打包后给别人,**单个 exe、双击直接出窗口、不用配环境**。

非目标(第一版不做,但不能挡住以后加):

- 远程传输(不在同一局域网)——后续版本。
- 端到端加密 —— 远程版再上。

---

## 2. 技术选型

**Go + Wails**。

理由:

- 编译产物是单个小 exe(十几 MB),双击出窗口,免安装;Windows 10/11 自带所需的 WebView2 内核,基本无感。
- Go 在网络 IO、并发(同时多个传输)、HTTP 服务、令牌桶限速上都有成熟标准库/生态,做传输/限速/断点续传顺手。
- 跨平台交叉编译方便(Win / Mac / Linux)。
- 前端用网页技术,桌面窗口(Wails 的 webview)和手机浏览器共用同一套界面,省一半工。

备选:Tauri(Rust,分发体验相当但开发慢)、Electron(界面好做但包大几百 MB,最不符合"单文件双击")。

---

## 3. 整体架构

一个 Wails 应用 = Go 后端 + 网页前端。

### 3.1 Go 后端职责

- **内置 HTTP/WebSocket 服务**:监听本机局域网 IP + 端口,供手机浏览器和其他电脑连接、收发文件、推送进度。
- **局域网设备发现(mDNS)**:同一局域网内自动发现其他正在运行的实例,用于电脑↔电脑。
- **文件收发**:上传(接收)、下载(发送),支持断点续传。
- **限速**:令牌桶,全局总闸 + 每任务单独限速,取两者较小值。
- **接收确认**:有发送请求时挂起,通过 Wails 事件通知前端弹窗,用户同意才放行。
- **二维码生成**:把本机局域网地址 + 端口 + 一次性临时码生成二维码给前端展示。

### 3.2 网页前端职责(桌面窗口 + 手机浏览器共用)

- 设备列表(mDNS 发现的电脑)。
- 拖拽文件 / 文件夹区域。
- 传输任务列表:进度条、实时速度、剩余时间、每任务限速调节。
- 速度档位切换(全速 / 普通 / 省流)。
- 二维码展示(供手机扫)。
- 响应式:手机访问时自动切换为适配手机屏的布局。

---

## 4. 两条传输通道

| 通道 | 发现方式 | 传输方式 |
|------|---------|---------|
| 电脑 ↔ 电脑 | mDNS 局域网自动发现 | 通过对方的内置 HTTP 服务收发 |
| 手机 ↔ 电脑 | 手机扫电脑显示的二维码进网页 | 在网页里上传/下载,经电脑端 HTTP 服务 |

---

## 5. 核心机制设计

### 5.1 限速

- 用令牌桶(如 `golang.org/x/time/rate`)包在传输的 io copy 流上。
- 两级:**全局限速器**(总闸)+ **每任务限速器**;实际速率取两者较小。
- 档位 = 预设数值:全速(不限)/ 普通(中等上限)/ 省流(低上限);也可手动填具体上限。
- 改限速即时生效(运行中可调),不需要重启任务。

### 5.2 实时速度 / 进度

- 后端按固定间隔(约每秒)统计每个任务已传字节、瞬时速度、剩余时间。
- 通过 WebSocket(给手机网页)和 Wails 事件(给桌面窗口)推送到前端展示。

### 5.3 断点续传

- 每个传输分配唯一 ID;服务端记录已接收/已发送的字节偏移。
- 中断后下次从偏移处继续:
  - 下载(电脑发给对方)方向:用 HTTP Range。
  - 上传(对方发给电脑)方向:分块上传 + 记录已落盘偏移,续传时带上偏移。
- 任务状态:等待确认 / 传输中 / 已暂停 / 已完成 / 失败。

### 5.4 整文件夹传输

- 前端遍历文件夹,逐个文件上传并携带相对路径。
- 服务端按相对路径重建目录结构。
- 断点续传以单个文件为粒度。

### 5.5 接收方确认

- 收到发送请求后,后端挂起该传输,触发前端弹窗(桌面用 Wails 事件,手机用 WebSocket)。
- 用户点"同意"才真正开始落盘;"拒绝"则通知发送方被拒。

## 6. 安全

- 扫码网址带**一次性临时码(token)**,防止局域网内其他人乱连。
- 第一版局域网内走明文 HTTP(同一 WiFi 下风险可接受)。
- 接收方确认机制兜底,防止被动乱收文件。
- 远程版再引入 TLS / 端到端加密。

---

## 7. 错误处理

| 情况 | 处理 |
|------|------|
| 网络断开 | 任务标记为已暂停/失败,支持断点续传或重试 |
| 端口被占用 | 启动时自动尝试换端口 |
| 找不到设备 | 前端提示,可手动输地址/重新扫码 |
| 接收方拒收 | 通知发送方"已被拒绝" |
| 磁盘满 / 写入失败 | 任务标记失败并报错提示 |
| 文件校验不一致 | 提示传输损坏,可重传 |

---

## 8. 测试策略

- **单元测试(Go)**:限速器行为、断点续传偏移计算、传输协议处理、mDNS(可 mock)。
- **完整性测试**:传输完成后比对源/目标文件哈希,确保一致。
- **集成测试**:本机起两个实例互传,验证发现 + 传输 + 续传全链路。

## 9. 实现里程碑(第一版顺序)

1. **骨架**:Wails 窗口跑起来 + 内置 HTTP 服务 + 显示本机局域网地址 + 二维码。
2. **基础传输**:手机扫码上传/下载单个文件,桌面窗口看进度。
3. **文件夹 + 断点续传**。
4. **电脑间 mDNS 自动发现 + 互传**。
5. **限速**:档位 / 上限 / 每任务,加实时速度显示。
6. **接收方确认弹窗**。
7. **打包成单个 exe**(以及交叉编译其他平台)。
